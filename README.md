# PSU Sales & Inventory System

IT8 Advanced Database - Final Drill. A full-stack sales and inventory system for Palawan State University:
**HTML + JavaScript** (frontend) -> **PHP** (backend API) -> **MySQL/MariaDB** (database, run on XAMPP).

**Intended users:** Cashiers (record sales), Inventory Clerks (products, suppliers, purchase orders), Admins (reports, users, backups).

## Setup (XAMPP, Windows)
1. Install XAMPP. In the Control Panel start **Apache** and **MySQL**.
2. Copy this folder to `C:\xampp\htdocs\psu_inventory\`.
3. Create the database - choose ONE:
   - **Easiest:** open `http://localhost/psu_inventory/install.php` (runs `database/01_schema.sql` + `02_sample_data.sql`).
   - **Manual:** in MySQL Workbench / phpMyAdmin run `database/01_schema.sql`, then `database/02_sample_data.sql`.
4. Open `http://localhost/psu_inventory/` and sign in.
5. DB settings (user `root`, empty password) are in `config.php`. Requires MariaDB 10.2+ or MySQL 8.0.16+ (CHECK constraints are enforced).

## Demo flow (for the video)
1. Log in as `cashier` -> POS -> sell 2 x Notebook A4 (Cash) -> receipt prints.
2. In Workbench: `SELECT * FROM sales ORDER BY id DESC LIMIT 1;` and `SELECT stock FROM products WHERE code='PROD-003';` (stock dropped by the trigger).
3. Run `03_required_queries.sql` blocks one at a time.
4. Run `04_constraint_tests.sql` T1, T7, T8, T10 and show the errors.

## Known limitations
- Single store/branch; no discounts, returns/refunds or partial payments.
- Tax is one global rate (`TAX_RATE` in `config.php`), not stored per product.
- Auto-backup downloads a file when an admin signs in; it is not a server-side scheduled job.
- PDF/Excel export libraries load from a CDN, so exports need internet.
- Seed data is generated; real use would start from empty tables.
